# 模块适配重新设计：先明确职责与假设

2026-09-22。用户要求先理解项目和模块，再形成适配设计；不可持续局部试改后用结果追认合理性。实现与新增实跑已停止。本文件记录设计判断和实施前必须解决的事项，不是适配成功报告。

## 纠正上一轮设计判断

原PDM的abstract_pdm_closed_planner.py先用内部控制器/车辆模型模拟候选，将模拟状态交给scorer，再由generator输出所选参考轨迹。这是参考轨迹与预期执行状态的职责分工，不能仅凭二者不同就判为错误。上一轮把模拟状态直接替换为CARLA PID的参考，缺少控制结构论证；两批闭环失败，该方案没有晋升为默认。

固定±1m偏移在当前车道内不能容纳整车，是实际的候选生成域问题；但取消偏移后仍失败，不能据此认定适配问题已解决。它与“参考/模拟状态的职责不同”必须分开处理。

## 项目真正需要的共同底座

研究点一检验有限预算下P/F获取与真实规划反馈的价值。共同底座必须：

- 在只有本车合法信息时就有可解释、可执行的基本驾驶行为；所有Ego/P/F/PF臂使用同一底座。
- 获得P/F后允许相同规划器基于真实新证据改变方案；控制保护不能持续接管并掩盖证据作用。
- 同一物理时刻的信息迭代不推进车辆状态、时钟或控制器历史；完成请求内环后才执行最终方案。
- 能追溯观测、预测、参考轨迹、预计执行轨迹与实际控制，分别评价，不混成一个trajectory字段。
- 任务范围、路线/动作空间和规划时域由论文问题与证据覆盖共同决定，不能只按某个模块容易通过的场景反向裁剪。

## 应采用的职责与接口

1. **感知与跟踪**：当前传感器→带来源、时标及有效位的目标状态/历史。观测误差、漏检、速度估计及不确定性不能被解释为完备环境；本轮没有证据要求重训检测器或重写tracker。
2. **证据适配**：将本车信息和实际购得P/F统一到明确坐标与决策时刻，保持实体、来源、模式及可用范围。缺失未来区间须有明确策略，不能为迎合规划器静默外推。
3. **候选生成**：输出供跟踪的参考轨迹，包含统一参考点下的t、x、y、heading、v及必要的a/curvature。完整机动应符合路线、车道、车身尺寸及可执行运动约束；不能只检查短窗口内尚未完成的横移。
4. **执行预测与评分**：由参考轨迹、当前自车状态和明确的跟踪器/车辆模型，推演预计执行状态后评价。预计状态是评分依据，不能未经论证再作为第二个控制器的参考。若内部跟踪模型与实际执行器不一致，必须说明允许的误差及依据。
5. **车辆控制**：消费参考轨迹和当前自车反馈，产生CARLA实际支持的控制量。速度/加速度设定与油门/刹车不是同一量；初始化、挡位、控制延迟、转向映射、饱和与积分状态均属于这一模块的职责。停车与恢复条件必须来自任务/参考语义，不能靠短路径或单帧低速猜测。

上层Agent读取的是明确的参考方案和基于已知证据的评价摘要；预计执行轨迹可单列。任何评分都不是校准安全概率。

## 对现有模块的判断

| 模块 | 当前判断 | 实施前必须回答 |
|---|---|---|
| V2Xverse单车检测、AB3DMOT | 可继续作为候选复用；已接通不等于质量合格 | 输入域、时标、历史有效性及任务相关目标是否满足要求 |
| PDM候选/评分思想 | 有复用价值，不能因此认定整套可直接迁移 | 候选动作域、完整几何合法性、预测覆盖、打分含义是否符合目标任务 |
| nuPlan式内部车辆模型/LQR | 不能直接代表CARLA PID及当前车辆的响应 | 状态量是否可观测、控制模型是否对应实际执行接口、哪些假设需要替换 |
| 原CARLA PID参数与接口 | 工具实现可用，项目适配尚未成立 | 参考轨迹的速度/几何语义、起步/挡位、低速横向控制及停车保持怎样闭合 |
| 模拟轨迹直接交给第二个PID的新方案 | 本轮验证失败，不作为已接受设计 | 必须先解释双层控制结构为何成立，不能继续逐参数试补 |

## PDM继续或退出的判据

仅当改动能落在清晰的地图/证据接口、候选合法性和车辆执行适配中，同时保持可解释的共同规划机制，才继续把PDM作为主底座候选。

若需要同时重写候选生成、内部预测/评分和实际控制，或只能依赖大量场景专用规则、特权状态、缩短任务范围才能运行，则应判定“原PDM作为低成本共用底座不合适”，重新比较其他候选，而不是继续称薄适配。其他候选也要核实输入权限、P/F接入与执行模型，不能直接宣称更换即可解决。

当前结论是：**现有PDM→CARLA拼接方案未通过适配验收；不能直接作为主实验底座。PDM能否通过合理成本的重新设计满足项目，尚不能作肯定结论。** 这不是证明PDM算法永远无法用于CARLA。

## 设计完成后才允许验证的顺序

先写清任务域、模块输入输出、参考点/坐标/时标、车辆状态和控制模型、机动约束、P/F消费方式及失败语义，再为每一项提出可以证伪的验收条件。

验证顺序应为：已知可执行参考轨迹的独立执行器检查 → 理想当前观测下的规划/执行接口检查（明确仅诊断）→ 真实本车感知链 → 同一底座的P/F对照。前一级未满足，不把失败归给后一级，也不直接扩大训练或方法实验。试验用于检验事先确定的设计假设，不替代设计本身。

在完整设计及替换/退出判断形成并经用户审阅前，不继续修改控制实现或新增闭环实跑。
