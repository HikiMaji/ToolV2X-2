ToolV2X：主实验底座与方法收敛复核
核查日期：2026-09-20。
结论与证据边界
建议保留“V2Xverse 纯 V2V + P/F + LLM 反馈调用”，将“整套 nuPlan PDM-Closed 迁移”收敛为“有原实现等价性测试的 PDM 规划核心 + CARLA 路线/地图薄适配”。这是一项基于论文与源码的工程建议，不是已运行验证的主实验结果。CoDriving 用作原生完整系统参考；它不是无需适配即可接 P/F 的即插即用备胎。CoLMDriver/InterDrive 必须加入相关工作和外部系统比较。
本轮核查了 PDM 原论文及关键官方函数、PDM-Lite、CoDriving、CoLMDriver、OpenCDA 的实际接口。当前容器 Python 3.13，未安装 nuplan/carla；尝试取得运行依赖遇到 DNS 连接失败。因此没有运行官方 PDM 整链、CARLA、真实传感器检测、MTR 或 LLM，也没有完成原版复现或闭环验收。此前简化几何 occupancy 示例不作为本次系统可用性证据。
一、新增核查结果
1. CARLA 原生 PDM-Lite 存在，但不是合法感知输入下的现成替代
官方 README 明确称其为 privileged expert。AutoPilot 直接访问模拟器，且使用 CarlaDataProvider.active_scenarios 处理特定场景。官方安装脚本下载 CARLA 0.9.15；CoLMDriver/V2Xverse 生态的相关参考入口使用 0.9.10.1。故“CARLA 原生”不代表“输入权限和版本已经兼容”。
PDM-Lite 可作为特权参考、数据采集参考和原生规则实现的补充。不能将其直接读到的全局 actor、scenario 或控制信息引入 ToolV2X 主方法。去除特权后需要重新验收，不能继承原分数。
2. CoLMDriver 是必须处理的近邻
CoLMDriver 已有大模型车车协商、反馈修订、独立 waypoint 网络及 InterDrive 交互评测，并提供 ideal/realtime 模式和 CoDriving 比较入口。ToolV2X 不能宣称首个“大模型+V2V+反馈+数值规划”。更窄的区别是：在远端上下文默认不可见时，基于已实现的驾驶修订，在预算内选择获取哪一种私有能力证据或停止。
CoLMIN 2026-09-04 预印本进一步讨论多意图协商和反思。本轮只取得其摘要，未完成全方法/源码复核，故只将其列为需要继续对照的近邻，不据此判断完全重合或完全不同。
3. PDM 核心可与上层地图服务分开考虑
官方 PDMScorer 主要消费候选状态、occupancy、centerline、route lane IDs、可行驶多边形。所核对 scorer 中地图 API 的直接查询为 TTC 分支的 intersection membership。整套 AbstractPDMPlanner 的路段搜索/初始化需求则更大。
建议从 CARLA 同版本静态地图及预设路线构建中心线、route IDs、lane polygons、intersection polygons、限速及合法信号约束，再调用原 PDM 核心。不能把“scorer 直接查询少”误解为“地图只需一个布尔函数”；路线拓扑、边界、方向和原点变换仍须真实正确。
二、PDM/F 接口的具体风险
1. PDMGenerator._update_leading_agents 使用未来 occupancy 位置，但速度来自 unique_objects 的目标状态。外部预测必须保证未来位置/速度的语义一致。
2. PDMScorer._calculate_ttc 仍读取目标 heading；get_collision_type 调用 is_track_stopped。只替换 polygon 和 IDM 速度仍可能不够，应统一查询目标在对应预测时刻的中心、朝向、速度和尺寸。
3. PDMScorer._aggregate_scores 将 progress 除以当次候选中的最大 progress，再组合乘性/加权项。不同调用阶段的总分不天然可直接比较；它不是校准风险概率，更不是独立 teacher reward。
4. PDMObservation 默认 observation_sample_res=2，通过整数整除映射时刻。规划内部为 0.1 秒时，occupancy 默认为 0.2 秒采样。应明确选择保留此语义或统一到 0.1 秒，所有实验臂相同。
5. observation 范围要求约为 max(output_horizon, proposal_horizon + 1s)；TTC 实际偏移按固定索引访问。不能仅改变 dt 而不检查 TTC 偏移含义。
6. 原 PDM proposal 4 秒、输出 8 秒与现有 F 3 秒不同。3 秒输出/2 秒 proposal 可作接通配置，但不宜仅为旧 wire 永久压缩规划视野。应核对模型真实输出范围，再确定版本化扩展或显式 fallback 区间。
7. 多次 PLAN 属于同一物理时刻的信息迭代，不能推进内部物理 iteration、碰撞历史或路线进度。相同 evidence 的重复执行用于确定性/费用检查；有意义的 self-refinement 不能靠重复确定性调用伪造。
三、建议的共同 PLAN 实现边界
使用 CARLA/数据入口构建 PlanningScene，只包含以下合法数据：
- 本车状态、实际车辆几何、坐标变换与历史；
- 决策前给定的路线、同版本静态地图与公开/本车观测到的信号；
- 本地单车感知/跟踪，以及合法购得、派生后的目标与预测；
- 每个字段的来源、有效时段、模型/context 身份。
该对象不保留 simulator World/Actor 句柄；PLAN 不能在执行时绕过接口再读全局车辆。原 PDM 的 nuPlan 数值类型可保留在 planner 进程内部。旧 CARLA、感知/预测和 LLM 环境不必强塞入同一 Python 环境，但跨进程表示、调用成本与失败语义必须记录。
复用 BatchIDMPolicy、候选生成、PDMSimulator、评分结构及紧急制动逻辑。新增路线/地图适配与时间索引目标状态接口；所有改变列出文件级差异。先在相同 nuPlan 输入、中心线、候选与配置上做等价性测试，再验证 CARLA 坐标、车辆几何和控制跟踪。不要只因为保留类名就声称原版复现。
四、F 消费不要成为新的巨大研究任务
首版可明确使用 top-score mode；原始六模式及分数仍完整归档，并披露实际消费方式。Top-1 不等于没有预测信息，也不等于完整利用不确定性。研究点一不必以发明多模态风险融合算法为前置条件。
在有效基线之后增加 top-k/多模态适配消融。若使用 sum(p_m * cost_m)，需说明分数是否归一化/校准、是否有截断概率质量、多来源预测如何去重、模式索引不跨来源对齐。多车单体边缘分布不自动给出联合场景概率；不能将该表达式直接叫作真实碰撞概率或安全保证。不要对每个世界先分别归一化 PDM 总分再无说明地求期望。
F 质量同时检查同上下文预测误差与下游规划价值。全体 ADE 优于恒速既非充分也非必要条件；关键场景的漏检、漏报冲突、误刹、进展和实际成本同样重要。仅一次开发失败不否定 F；系统性劣于恒速且无任务收益时暂停依赖它训练 Agent。
五、数据与坐标门槛
V2Xverse 原生路线来源可复用，但必须绑定到实际录制版本、路线文件和地图。已保存局部 goal 不是完整路线或 nuPlan map API。
官方采集脚本示例 LiDAR 相对车体位置为 x=1.3m、z=1.85m、yaw=-90度；因此点云局部坐标不能直接当车体或 PDM rear-axle 坐标。需要明确世界、车体、传感器、rear-axle 的变换、左右手系、角度单位及车辆尺寸。
核对 simulator tick、传感器 tick、保存间隔、文件编号与绝对时间。历史重采样只能使用决策时刻已到达的信息，不得用未来状态填补。不能把稀疏存储序列视为原生 10Hz。
主实验采用两车真实传感器检测/跟踪；GT actor 仅用于评价和标明的理想感知诊断。屏蔽 RSU、expert hazard、其他车辆控制量和未购得 peer 表。第一批优先预声明遮挡和信息不对称场景，避免把必须协商的复杂换道场景当成无 ego-plan 条件预测的基本验收。
六、Agent 与训练标签修正
Agent 只决定 P-current/F-current/P-change/F-change/STOP；初始与返回后的 PLAN 由执行器强制调用。对话数据应区分 Agent 决策和执行器动作，不把强制 PLAN 序列当作模型学会自由规划调度。
输入使用合法 scene/route、当前与上次 trajectory、真实新证据、可复算的候选变化和预算。提供物理量时声明基于已知证据，不把“已知目标没有冲突”解释为“不可见区域安全”。不把 PDM 总分、score margin 或空 P 返回解释成真实安全置信度。
两次调用 teacher 必须是两阶段决策，不能只用首次工具返回后的即时质量贪心打标。离线未来标签只负责评价候选结果，不进入 Agent 输入。
特别区分：逐样本看完全部未来后选择最优分支，是事后知情 oracle；它的收益是上界，不保证在线模型可达到。受限信息 teacher 应根据合法状态和训练折上的结果估计期望价值，并在独立路线/录制组上评价。避免利用场景 ID 或事后收益写解释。可保留多动作效用和近似平局，而非制造过度确定的唯一答案。
冻结反馈实验应分两层：
- 在相同动作/模式下只替换第二次 current 请求的 tau，检验检索参数的反馈作用；
- current-only 下保持相同动作空间，比较策略看到/看不到 revision；
- 再单独加入 change 检验其额外价值。
  不能把 frozen 臂删除 change、adaptive 臂保留 change 的全部差异都归因于 tau1。
七、评价和停止条件
区分固定时刻证据获取内环与车辆真实闭环。前者可使用独立 GT actor future 做非反应式规划代理评价；后者车辆会运动、信息会变旧，必须处理 deadline、timestamp、取消/过期返回与实际低层控制。不把暂停仿真等待 LLM 的结果叫实时驾驶。
固定环境/PLAN/P/F 比较规则、小模型、prompt-only LLM、SFT LLM，并报告 LLM 本身成本。同一首轮前缀的 frozen、same-evidence 和同总预算 one-shot 是方法归因对照。CoDriving/CoLMDriver 属于外部完整系统参考，其输入和能力不同不能直接当“只换策略”的消融。
建议阶段：
A. 固定源版本、路线/地图/时标、世界模型白名单。
B. 原 PDM 核心与薄适配的等价性、Ego-only 路线及真实观测测试。
C. 单车预测/CV、P/F/PF 和同证据重复验证，区分获得、使用与真实获益。
D. 建立独立分组上的可观测策略价值，再构造两阶段 SFT 数据。
E. LLM/小模型与 feedback/one-shot 比较，最后验证闭环和时延。
若证据作用需要不断重写 planner、合法路线时钟无法建立，或可靠预测/候选集无法覆盖任务，应停止扩大范围，而非持续训练 LLM 掩盖底座问题。CoDriving 是完整系统备选研究路线，不是同接口零成本切换。
八、正式课题定位
研究点一：有限预算和远端信息不可直接见的条件下，大模型如何使用本地规划的实际结果与远端 P/F 返回，决定下一次获取哪种能力证据或停止。规划器和适配本身是共用基础。
研究点二：合法来源可能返回语义错误证据时的可信评估、拒绝和风险受控处置。receipt/签名不是语义正确性证明，同一恶意 peer 的第二次回答也不自动构成独立核验。STOP 仅表示停止远端获取，不等于车辆停车或安全保证。
