## Important

### I1　部分失效监督被删除后仍可拟合成功，已解决

以下为`5e89769`初审发现及其当时证据。位置为该版本`scripts/rq1_score_revision/no_miss_constant.py:47`、`:58`、`:60`和`:62`。

`available`先删除`finite=False`或对应基础特征为None的监督行。后续只检查六父集合是否仍完整，并对`status == unestimable`单独报错。因此，只要失效行所在父还有其他有效监督，模型就会用剩余记录重新计算权重和scaler，并保存`status=ok`。J_zero也会继承这个已经缩小的I_zero监督集合。

这个输入状态来自实际接口。`heads.window_features`在数值失败时会设置`finite=False`、特征为None及`numeric_failure`，不是只会产生`unestimable`。正常流程的这类失效不会被当前第60行拦住。

SDS要求先筛源族，再检查支持和所有六父，不得将不可估行或父删除后继续拟合。当前实现虽然在coverage中记录了`n_excluded`，仍改变了参与估计的监督及其权重。若失效集中在某些真假条件或攻击层，会带来选择偏差。保留评价分母不能修复训练总体已经改变的问题。

审核仅针对这一未被现有测试回答的疑问运行了合成定点验证，调用真实`fit_regime`与`fit_zero`优化器，没有mock，也没有读取真实特征或运行真实批次。结果如下。

| 输入改动 | D_zero状态 | D_zero样本数 | I_zero状态 | I_zero样本数 |
|---|---|---:|---|---:|
| 72条监督中一条finite=False，状态numeric_failure | ok | 71 | ok | 71 |
| 72条监督中一条D_head特征为None，状态numeric_failure | ok | 71 | ok | 72 |

两种情况均保留原六父。第一种情况两个模型的coverage都明确记录`n_excluded=1`，但仍成功估计。第二种情况说明该错误可以只影响一个基础头。

最小修正是在计算权重和scaler前，若对应方法的`available`未覆盖全部`selected`监督，就将该方法标记不可估并保存排除原因。D头失效只影响D_zero，I头失效应使I_zero及依赖它的J_zero不可估；旧基线仍可输出。不要通过补0、删行重加权或改支持门槛解决。补充一项覆盖上述两种输入的定点测试，并核对失败方法仍以Unknown保留共同评价分母，且不能通过保留判据。

现有测试覆盖了删除整个父、缺Delta及特征内部NaN。特征内部NaN会留在available中，由fit_base拒绝；它没有覆盖本问题中进入available前已经被删除的行。
