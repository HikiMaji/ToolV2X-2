## 三个补充评分，预先确定

- Cond：R=-features.D_head[1]，必须有限且非负。空未报为 0。直接复用已保存、已通过重建核对的 p_D 窗口统计，不重建模型。
- MissCount：R=sum(n_minus)。无条件的未报次数控制，检查新增拒假是否仅因多给了拒绝预算。
- BaseTail：R=-saved_scores.Count。扩大原 Count 拒绝区的控制，检查收益是否只是移动原评分门限。此控制允许带符号评分，不引入平移常数。

保留原 Count 和 D_zero 输出作参考，不修改它们。不尝试选择最有利补充分支。

## 正常校准与判决

每个 regime 独立使用它原有 cal 中的完整 clean 主真分母。原权重和为 1，先求 Count 误拒 e_B，再取 delta=min(.02,max(0,.05-e_B))。

对每个补充分支，在 Base 正常可读且非拒绝、query 合法且有 reject_eligible 的 clean 记录上形成评分候选。Cond/MissCount 只取正值，BaseTail 取全部有限值。选择新增真实误拒全局质量不超过 delta 的最小候选 tau，严格 R>tau 拒绝，平分不拒。没有候选或 delta=0 时关闭并记录原因。必要候选评分数值失败时关闭该校准分支，不删失败样本。

在线顺序：Base 拒绝保持；Base 故障未知保持；模块关闭或评分失败保持 Base（记录关闭/degraded）；其他满足原拒绝资格且 R>tau 才改拒绝；其余保持。新判决不反馈前端。在线函数不读取标签、family、k、parent。

预期同输入下采纳集合缩小，拒绝集合扩大，FA 不增加。此相对性质不证明净收益。新域真实误拒仍实测，不把 clean cal 约束称总体风险保证。

## 指标与保留条件

复用既有统计函数或其相同口径。对 cal/eval 都报告真假六格、CD、逐 family/k、逐父、原判决到新判决转移、首窗、配对首次采用延迟及从未采用 epoch 比例。覆盖、故障、关闭与 unknown label 单列。

时效明确复用 scripts/rq1_score_revision/no_miss_constant.py 的 _paired，只纳入 primary 真 query 时刻组成的生命周期。从未采用率按父/epoch均衡，共同曾采用集合的延迟差按该集合父/epoch重新均衡后取加权中位数。没有共同曾采用 epoch 时记支持不足，时效门槛不得默认通过。不混用 original.trajectories 纳入同 epoch 未知标签时刻的首次采用定义。

Cond 对 Count 的原定开发保留条件全部满足才 retained：eval 总真误拒<=.05；总体及每个已评价假层 FA<=.05；TA 损失<=.02；CD 增量>=.01；真 epoch 从未采用比例增加<=.02；共同曾采用 epoch 的配对首采用延迟差加权中位数<=.5秒。三 regime 分别裁决且不平均抵消失败。无有效新增判决或分支关闭不算通过。保留原 cal 缺失 family/k 的限制，不转为覆盖充分。

两个控制采用同一 clean 预算和门限算法，分别完整报告风险。只有 Cond 比满足同等风险条件的 MissCount 和 BaseTail 的 CD 各高至少 .01，才称本次建立超出简单追加拒绝的条件增量。若可用模块通过但该对照未通过，明确区分有限效用与条件机制归因；控制风险不合格时不能直接称同风险优势，归因记未充分建立。

这是一次开发工作点比较，不做事后门限扫描、置信区间装饰或宣称 CCF-B 方法贡献已完成。若局部/整体不通过，按分项原因记录，不改门槛。
