## P1，正式运行前必须修复

### 1. report同时保留多套完整Python行，超过当前容器可用内存

位置`run.py:309–325`，以及`evaluate:203–238`产生的全部轨迹明细。

每个variant把全部job读入rows；main_rows还保留main全量，下一variant又读第二份全量，reports继续保存五份分层和轨迹明细。score阶段每job一份行的内存方式在这里被取消。仅删除main_rows并存不能保证单份全量能装下。

现场只读memory.stat显示anon为1,456,091,136字节、file为431,419,392字节，上限2,147,483,648字节。文件缓存可以回收，但当前匿名内存已占约1.36GiB。用一个实际prediction返回结构作JSON往返并加decisions后，递归对象大小约8,865字节。这个单行估算不能当精确RSS预测，但仅旧92,157行两份已约1.52GiB，尚未计新增job、分层对象、numpy临时数组和matplotlib。120条fixture通过不能支持这里的真实负载。

最小修法是保留现有统计定义，改为紧凑列数组或小型SQLite表存评分标量，逐variant、逐split处理。门限扫描只保留必要数值列；轨迹指标逐epoch聚合，明细落盘；main predictions及case候选流式写，不因后续敏感性保留main全量。按主会话已明确要求，将本任务增量内存控制在约200至300MiB，并保留一次该负载路径的峰值证据。无需重跑native前端或核心测试。

### 2. 校准只取最宽安全门限，正确质量平手时会被未知标签分数影响

位置`run.py:123–166`，特别是147–163行。

当前扫描只累计错误质量，并一直放宽到下一步超预算或0。blocks包含全部行，未知标签或仅辅助框的分数也会改变最终门限。更宽门限虽然不会降低cal正确数量，但在正确质量完全相同时不符合已审约定中的保守平手处理，并会改变eval假采纳。

定点三行fixture确认，主真分数3、主假分数-2、未知标签分数0.1时，当前得到A=0。A=3有完全相同的主真采纳1和主假采纳0。另一个eval假分数0.5在A=0时被采纳，在A=3时未知。此差异不是研究机制收益。

最小修法是在现有tie累计扫描中同步累计对应正确类别的加权质量，在满足总体及各层错误预算的候选中最大化正确质量。正确质量并列时A取更大、R取更小，关闭分支也纳入候选。未知标签不能为同效门限提供放宽理由。保留tie整体纳入、共同总体分母及0分未知。新增一个正确质量平手fixture即可，原穷举fixture也须按同一目标更新，不能只复现当前最宽门限算法。

## P2，结果形成前必须在同轮修复

### 3. 最终指标没有family与k的联合分层，不能核对已声明的分层风险

位置`run.py:210–212`及`301–320`。

cal确实对每个非空family/k组合施加了5%经验约束，但evaluate只分别按family、attack_k分层，没有输出family/k联合六格。比如F2的k=3高假采纳可以被同族k=1/2及其他族k=3分别平均掩盖。只有各自边际表不能复核“每族/k假采纳相对同政策MATE和T都报告”的要求。

最小修法是增加同一primary、同一weights计算的family/k联合六格及父/epoch/时刻计数，并记录对应cal层是否缺失。保留已有单独family和k边际表作补充，不重新拟合或改变门限。

### 4. 自动retain_increment没有执行已批准的保留条件

位置`run.py:272–282`及`320、365–366`。

当前自动决定只检查总体两类风险<=5%、clean窗口NLL降低和correct_definite增大。它未核对family/k风险相对T/MATE的增量、真采纳损失及首次采纳延迟，且新增了必须降低NLL的保留条件。完整设计第11节的预声明经验容差为风险增量+2个百分点、真采纳损失<=5个百分点、延迟中位增量<=0.5秒；证据不足时应报告不足。当前规则可能在正确明确率提高但真采纳损失过大、某个攻击层风险明显增加时仍输出retain_increment=true。

最小修法无需增加自动决策框架。先让该函数仅输出同政策的观察差异和可估状态，保留决定标为待Task 3按批准标准裁决；或者准确执行原有条件。不要把当前简化规则写成“预声明开发标准”，也不要因结果不好另加NLL门槛或改经验容差。

### 5. 未形成target query与target标签歧义没有独立分母

位置`native_adapter.py:326–378、435–452`和`run.py:219–238`。

attach_labels只对最终query_truth=0计target_query_rows。complete保留这个成功标假计数，但target未形成query、存在注入实体相容query却因GT/角色冲突保持未知、以及只有output的新生情形，没有分别统计。evaluate的unknown_labels混合了整个攻击背景的未知标签，不能恢复主target的缺失覆盖。若F3导致更多关联歧义，主假query六格会变小，而当前产物无法区分是前端没有生成目标还是标签不能判断。

最小修法是在离线标签阶段，按预声明注入实体和时刻记录target/occluder的query出现、output出现、唯一可标假、与GT相容/角色冲突及无query的计数。歧义仍保持未知，不能为补分母强标假。每个攻击任务附一份紧凑覆盖统计，报告每族/k的尝试、UNREALIZABLE、成功注入、无target query及标签未知覆盖。主六格继续仅使用确实存在且标签明确的query，不把不存在的query伪造为unknown样本。
