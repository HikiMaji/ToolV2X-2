# 研究点一共用驾驶底座适配

用户已授权根据项目需求修改模块；目标是可靠、因果、可比较的共同PLAN及执行接口，不是原版行为复现。保留此前所有修改和失败产物，不提交/推送。

## 需求与范围

- PLAN只读已授权PlanningScene。Ego/P/F/PF共用同一规划与执行逻辑，不按实验臂、场景标签或GT改控制。
- 候选评分、给上层的方案及低层跟踪须说明是否同一动力学轨迹，不能让低层追踪瞬时横移的参考折线。
- 显式返回有效性/选择状态和带时标的速度。分数仅为候选相对量，不是置信度。无可行候选不能静默argmax=0。
- 当前单车道路段、小速度上限与CARLA0.9.10.1为有限运行适用域；输入权限、时间语义、信息公平性不可放宽。
- 保留v1原版对照入口，新增版本化项目适配；不训练、扩展研究点二或直接接方法收益实验。

## 实施顺序

1. 保存当前六个相关文件快照（已完成）。两项只读并行分析检查规划可行性和控制参考，主agent核对调用链与实际CARLA API。
2. 为v2规划的连续初态、可行性判定、显式速度、同一时刻重复确定性写失败测试，再实施最小适配。保留原版独立上游等价性测试。
3. 为新的控制引用、低速保持/释放及校验写失败测试。复用现有PID或小型适配，依据根因决定，避免重复搭建框架。
4. 更新本地worker/probe，保存车辆实际控制与挡位等自车状态；将限域配置和停止条件预先写入运行spec。
5. 先定向测试与现有状态离线重放，再做一轮预声明的空路、静止前车、前车释放检查。保持旧结果独立，新条件不追溯重分类旧运行。运行前另存确切步数、阈值、修改和预算；必要时仅允许一次有明确新根因的修复复测。
6. 独立复算结果、执行审查和完整轻量回归，清理本次进程，更新STATUS和报告，区分工程适配通过与方法收益。

## 明确不纳入本批

大规模训练、正式研究评测、额外下载、P/F新采集、LLM策略及研究点二。感知/跟踪本批无实证需要则保持；可适配不代表必须改动每个模块。
