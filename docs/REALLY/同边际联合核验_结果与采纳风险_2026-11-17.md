# 同边际联合核验结果与采纳风险

2026-11-17。**本轮 Joint 不保留。原六段和追加三段资料的六项比较均未达到相对 Cond 至少 1 个百分点的 CD 增益。追加资料还揭示了冻结 Count/Cond 的超预算假采纳，当前不能宣称该组合已通过跨录制风险检验。**

原六段上 Cond 的条件反证增益仍成立。本轮没有推翻那些数值，但将其适用范围明确限制为已测开发域。不能只展示旧域正结果而省略新风险，也不能把本轮失败扩大成所有多车依赖方法无效。

## 1. 本轮已完成的具体工作

固定原 Count 三态政策、p_D、W10、资格和正常校准预算。只新增同边际联合条件反证 Joint 及简单组平均 Group，各自从原 Count 判断出发。没有恢复 Count 已拒绝的目标，没有重训单车模型，没有重选攻击种子。

正常拟合复用六个留父 D 模型，使用 17601 条正常候选时刻记录。1901 条记录包含非单例有效组，分布于五个父录制、73 个 query 生命周期。报告组合为共同报告1518条、共同未报136条、分歧247条。这些是候选时刻，不是独立道路事件。

从冻结网格选出的混合强度为 rho=0.25。它是模型参数，不是实测物理相关系数。原始正常拟合目标从0.76750555降至0.76514056，但这是rho的选择目标，不是独立验证。

随后按冻结清单处理三个当前20父之外、已有检测缓存的录制：
- train/2021_08_22_09_43_53，88扫描。
- train/2021_08_23_17_07_55，86扫描。
- validate/2021_08_21_17_30_41，157扫描。

仅补算一次必要FOV，没有训练检测器。15任务得到3个正常任务、6个可构造攻击和6个不可构造攻击。不可构造保留，不换seed，不计作防御成功。这些是历史开发资产中的追加确认资料，不是项目全新盲测。当前选用3车缓存是本批接入选择，不是算法永久车辆数限制。

## 2. 联合没有带来预定增量

CD为真采纳率与假拒绝率的均值。各域单独使用原分级权重，不合并抵消失败。

| --- | ---: | ---: | ---: | ---: |
| 原六段，mixed | 68.9599% | 65.2525% | 69.0309% | +0.0710 |
| 原六段，基线F1/评价F2 | 60.9269% | 57.2281% | 60.9070% | -0.0199 |
| 原六段，基线F2/评价F1 | 75.7355% | 72.4335% | 75.7186% | -0.0168 |
| 追加三段，mixed | 48.2873% | 48.2873% | 48.0031% | -0.2842 |
| 追加三段，基线F1/评价F2 | 53.4999% | 57.4061% | 53.4999% | 0 |
| 追加三段，基线F2/评价F1 | 52.1188% | 52.4095% | 52.1188% | 0 |

原六段mixed中，Joint仅将2条假未知转拒绝，同时把1条假拒绝转未知。真侧新增28条未知转误拒，6条误拒转未知，真采纳没有增加。不能把6条转未知写成恢复真实采用。

追加mixed中，Joint与Cond的真实决定完全相同，只把2条原来拒绝的假记录改为未知。两个追加迁移方案的主要真假决定与Cond完全相同。

正常评价的报告组合负对数损失也没有改善，数值越低越好：

| 正常评价域 | 独立模型 | 联合模型 |
| --- | ---: | ---: |
| 原六段 | 0.48879615 | 0.48975497 |
| 追加三段 | 0.53434862 | 0.53450323 |

因此，正常拟合目标的小幅下降没有在评价正常记录中复现，也没有形成所要求的真实性判断增量。不能由此断定物理依赖不存在，只能撤下当前分组、边际和混合模型组合已经有效的主张。

Cond在追加域仍增加了拒假效用，但mixed和F2_only假采纳明显超过5%工作预算。效用提高不能抵消风险失败。独立重建已确认这些是原 Count 模型、原门限及 Cond 规则的正确重放，不是本次状态路径修复或新数据接口错接造成。

mixed的41条Cond误采、F2_only的40条误采，均来自 validate/2021_08_21_17_30_41 的同一个F1/k2注入实体。对应F1/k2层假采纳分别为46.5909%、45.4545%。不能把40余时刻称为40余个独立攻击，以上比例也不是部署风险估计。

## 4. 主要误采为何不受本轮反证模块影响

对已保存预测作一次只读来源分解，没有运行新门限或新政策。

| 方案 | Cond误采时刻 | 原Count已采纳 | 没有有效未报且R=0、无拒绝资格 | 有反证但未达到门限 |
| --- | ---: | ---: | ---: | ---: |
| 追加mixed | 41 | 41 | 36 | 5 |
| 追加F2_only | 40 | 40 | 36 | 4 |

一个实际首窗记录的键为 `["748caf659d7d990e",117,98]`。三个来源为2488、2497、2506，当前事件为 `[1,1,-1]`，即两份报告和一个未知。窗口输入为 `(n_plus=2,n_minus=0,w=1,d=2,m=2)`。

Count给出采纳。Cond、Group、Joint的反证均为0，拒绝资格不成立，三者都继承采纳。

这准确定位了当前组合的能力缺口：**Count依据报告统计给出采纳，而后续模块只能用有效未报反证去推翻它。没有有效未报时，这条修正路径不起作用。** 在既定条件反证公式下继续调整rho，不能修复这36条零反证误采。该结论限于当前路径，不证明所有合法正报告信息都无判别价值。

不能因此直接规定所有R=0记录为未知，因为正常目标被各车共同报告时也可能R=0。任何采纳约束修订都必须同时评估真实采用代价，并明确其正报告依据。本轮没有实施这种新规则。

原域、追加域、各攻击族和首窗指标均保留在完整报告。未知标签不补假，不可构造不补成功，攻击中的重复真实背景不计入clean主真分母。窗口不是独立样本，三个regime不是三套独立录制。

## 6. 明确的方法取舍

1. **不保留本轮Joint为有效方法，不继续在本批上调rho、换门限或补攻击求通过。**
2. 保留Cond的代码及原六段局部增益事实，作为研究组件和对照。新增证据已阻止把Count/Cond组合称为跨录制风险合格的完整核验器。
3. Group仅保留控制。它在追加F1_only有局部增益，但假层仅一父，且原域表现较差，不能据此认领稳定联合贡献。
4. 后续优先需要明确采纳依据及正报告条件证据，特别是多份报告存在、却没有有效外部未报反证的情形。不能继续只在拒绝端叠加联合项，期待它解决这类采纳错误。
5. 这不是恢复K1或重建MATE，也不改变目标真实性核验问题。当前尚没有已确定的新采纳规则；不能用任意攻击先验、受控数量上限或“没有反证便为真”填补缺口。
